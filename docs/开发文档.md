# 本地工作导航网站 · 开发文档

| 项目名称 | 本地工作导航（Work Hub / NavHub） |
| --- | --- |
| 文档版本 | v1.0 |
| 编写日期 | 2026-10-15 |
| 运行形态 | 纯本地静态网页（单页面应用，双击即用，无需服务器） |
| 目标用户 | 个人 / 小团队，需要把日常办公站点集中管理 |

---

## 1. 项目概述

### 1.1 背景

日常工作中常用的站点分散在浏览器收藏夹里：公司 OA、禅道/Jira、GitLab、监控大盘、内部 Wiki、云控制台、多个环境的测试地址……收藏夹层级深、图标缺失、跨浏览器不同步，找起来很慢。

本项目做一个**纯本地的网址导航页**，把这些站点收敛到一个可自定义的工作台页面上，支持手动添加和**从浏览器收藏夹一键导入**，并允许更换背景打造个性化首页。

### 1.2 项目目标

1. **零门槛运行**：解压后用浏览器打开 `index.html` 即可使用，不需要 Node/Python 环境，不需要联网服务器。
2. **快速录入**：支持手动添加，也支持导入浏览器导出的书签 HTML，自动按文件夹生成分类。
3. **数据自主**：所有数据保存在本机浏览器中，不上传任何服务器；支持 JSON 一键导出/导入做备份与迁移。
4. **好看好用**：卡片式布局、自动获取站点图标、支持更换背景、支持搜索快速定位。
5. **可扩展**：数据结构与渲染逻辑分离，后续可平滑升级为浏览器插件或带同步的版本。

### 1.3 非目标（本期不做）

- ❌ 多用户账号体系、登录注册
- ❌ 服务端数据库、云端同步
- ❌ 直接读取浏览器收藏夹（浏览器沙箱限制，改为导入导出文件的方式；插件形态列入后续规划）

## 3. 技术选型

### 3.1 总体架构

采用 **纯前端单页应用（SPA）**，无构建步骤（或可选轻量构建），核心为「数据层 ↔ 状态层 ↔ 视图层」三层分离。

```
┌─────────────────────────────────────────────────┐
│                   浏览器                         │
│  ┌───────────┐   ┌───────────┐   ┌───────────┐  │
│  │  视图层    │ ← │  状态层    │ ← │  数据层    │  │
│  │ UI 渲染   │   │ Store     │   │ Storage   │  │
│  │ 弹窗/拖拽 │ → │ 增删改查   │ → │ 持久化    │  │
│  └───────────┘   └───────────┘   └─────┬─────┘  │
└────────────────────────────────────────┼────────┘
                                         ↓
                            ┌────────────────────────┐
                            │ localStorage / IndexedDB│
                            └────────────────────────┘
```

### 3.2 技术栈

| 层面 | 选型 | 理由 |
| --- | --- | --- |
| 结构 | 原生 HTML5 | 无框架依赖，保证「双击即用」 |
| 样式 | 原生 CSS3（CSS Variables + Grid/Flex） | 零构建；用变量实现主题与背景换肤 |
| 逻辑 | 原生 JavaScript (ES6+ Module) | 无需 npm；模块化便于维护 |
| 数据持久化 | `localStorage`（结构化数据）+ `IndexedDB`（背景图片二进制） | 结构化数据小、读写快；图片体积大，必须落 IndexedDB |
| 书签解析 | 原生 `DOMParser` 解析 Netscape Bookmark HTML | 浏览器内置，无需第三方库 |
| 图标获取 | 站点 `favicon` 多级回退 + 首字母色块兜底 | 避免依赖第三方图标服务，保护隐私 |
| 打包 | 可选：单文件 HTML 合并 | 极致便携，便于拷贝到内网机器 |

> **关于「无第三方依赖」的取舍**：引入 CDN（如 Tailwind、Vue）能加快开发，但会破坏「纯本地、离线可用」的核心诉求，因此本项目**默认不使用任何 CDN 资源**，所有代码与图标资源本地化。

### 4.1 功能总览

| 编号 | 模块 | 优先级 | 说明 |

| F1 | 站点卡片展示 | P0 | 主页核心，网格布局展示所有站点 |
| F2 | 分类管理 | P0 | 分类的增删改、拖拽排序、折叠 |
| F3 | 站点增删改 | P0 | 手动添加、编辑、删除、排序 |
| F4 | 收藏夹导入 | P0 | 解析浏览器导出的 HTML 书签 |
| F5 | 数据导出/导入 | P0 | JSON 备份与恢复 |
| F6 | 背景更换 | P1 | 预设壁纸 + 自定义上传 + 颜色主题 |
| F7 | 搜索过滤 | P1 | 站内实时搜索，支持拼音首字母 |
| F8 | 深浅色模式 | P1 | 跟随系统 / 手动切换 |
| F9 | 图标自动获取 | P1 | 自动抓 favicon，失败降级 |
| F10 | 键盘快捷键 | P2 | `/` 聚焦搜索，`Esc` 关闭弹窗 |
| F11 | 拖拽排序 | P2 | 卡片与分类拖拽 |
| F12 | 打开方式设置 | P2 | 新标签页 / 当前页，可单站覆盖 |

### 4.2 F1 站点卡片展示

**布局**：卡片式，桌面端一行 4–6 张自适应（CSS Grid `auto-fill`），移动端 2 列。

**单张卡片包含**：

| 元素 | 说明 |
| --- | --- |
| 图标 | 48×48，圆角；懒加载 |
| 站点名称 | 单行，超出省略，hover 显示全称 |
| 描述 | 可选，单行省略 |
| 状态 | 可选，hover 显示域名 |
| 右键菜单 | 编辑 / 删除 / 复制链接 / 置顶 |

**卡片交互**：单击打开链接；`Ctrl/Cmd + 单击`强制新标签页打开。

**空状态**：无数据时展示引导页——「手动添加第一个站点」或「从收藏夹导入」两个入口。

### 4.3 F2 分类管理

- 支持**一级分类 + 二级分类**（父子级），层级最多 2 层，避免过度嵌套。
- 侧边栏展示分类树，点击定位；分类可折叠、可拖拽排序。
- 提供「全部 / 常用 / 未分类」三个系统虚拟分类，不可删除。
- 「未分类」是**虚拟分组**（不在 `categories` 里，由 `categoryId` 为空的站点动态聚合而成），因此它的显示名存在 `settings.layout.uncategorizedName`，通过侧栏该条目的 `⋯` 菜单可重命名（≤ 20 字符，空值自动回退「未分类」）。
- 分类隔离策略：默认按一级分类分区平铺展示全部，也支持「点击侧栏只看单个分类」。

### 4.4 F3 站点增删改

**新增 / 编辑表单字段**：

| 字段 | 类型 | 必填 | 校验规则 |
| --- | --- | --- | --- |
| 名称 | 文本 | ✅ | ≤ 30 字符 |
| URL | 文本 | ✅ | 必须以 `http://` 或 `https://` 开头；缺失协议时自动补 `https://` |
| 归属分类 | 级联选择 | ✅ | 默认「未分类」 |
| 描述 | 文本 | ❌ | ≤ 60 字符 |
| 图标 | 自动/URL | ❌ | 留空则自动获取 |
| 打开方式 | 单选 | ❌ | 默认继承全局设置 |
| 是否置顶 | 开关 | ❌ | 置顶卡片排在最前 |
| 标签 | 多值 | ❌ | 用于搜索与筛选 |

**交互细节**：

- 表单支持「保存并继续添加」，便于批量录入。
- 删除需二次确认（或提供 5 秒撤销 Toast）。
- URL 重复时给出提示，允许强制保存。

### 4.5 F4 收藏夹导入（核心功能）

#### 4.5.1 导入流程

```
用户点击「导入收藏夹」
      ↓
选择浏览器导出的书签 .html 文件
      ↓
FileReader 读取文本内容
      ↓
DOMParser 解析为 DOM 树
      ↓
递归遍历 <DT><H3> 文件夹 与 <DT><A> 链接
      ↓
生成预览：分类数 / 站点数 / 重复项数
      ↓
用户确认导入方式（合并 / 覆盖 / 仅新增）
      ↓
写入 Store 并持久化
```

#### 4.5.2 解析规则

浏览器导出的书签文件是标准的 **Netscape Bookmark File Format**，结构如下：

```html
<!DOCTYPE NETSCAPE-Bookmark-file-1>
<DL><p>
    <DT><H3 ADD_DATE="..." >收藏夹栏</H3>
    <DL><p>
        <DT><A HREF="https://example.com" ADD_DATE="..." ICON="data:image/png;base64,...">示例站点</A>
    </DL><p>
</DL><p>
```

**解析要点**：

| 项 | 处理方式 |
| --- | --- |
| 文件夹层级 | `<H3>` 后紧随的 `<DL>` 为其子节点；映射为分类/子分类 |
| 顶层根节点 | 「收藏夹栏」「书签栏」「Bookmarks bar」等根容器**不作为分类**，其子文件夹提升为一级分类 |
| 链接 | `<A>` 的 `HREF` 为地址、`textContent` 为名称 |
| 内置图标 | `ICON` 属性常含 base64 图片，可提取复用（体积考虑：默认不保存，仅在无 favicon 时使用） |
| 排序 | 按 HTML 中出现顺序（即浏览器中的原始顺序）生成排序权重 |
| 编码 | 统一按 UTF-8 读取；若出现乱码，提示用户重新导出（Chromium 系默认 UTF-8） |

**兼容性**：Chrome / Edge / Firefox / 360 / Safari 导出的 HTML 均可解析。Safari 导出的为 plist 格式，本期**不支持**，需在 UI 中注明。

#### 4.5.3 导入冲突处理

导入时提供三种模式：

| 模式 | 行为 |
| --- | --- |
| **智能合并**（默认） | URL 已存在的跳过；新 URL 追加到对应分类；分类同名则合并 |
| **仅新增** | 仅导入本地不存在的 URL，不新建同名分类的重复项 |
| **全量覆盖** | 清空现有数据后导入（需二次确认，高危操作标红） |

导入完成后展示结果报告：`新增 128 条 / 跳过重复 12 条 / 新建分类 6 个 / 失败 0 条`。

### 4.6 F5 数据导出 / 导入

- **导出**：一键下载 `work-nav-backup-YYYYMMDD-HHmm.json`，内容包含分类树、站点列表、设置、背景引用。
- **导入**：支持选择 JSON 文件恢复，同样提供合并 / 覆盖选项。
- **自动备份**：每次数据变更后，向一个「上一版本」快照槽写入，误操作时可一键回滚（仅保留最近 1 份）。

> ⚠️ **风险提示（必须写入 UI）**：数据存放在浏览器 localStorage 中，**清理浏览器数据 / 使用无痕模式 / 更换浏览器或电脑会导致数据丢失**，请定期导出 JSON 备份。本产品**不设任何密码或访问控制**，请注意不要把个人凭证类信息放入导航条目。

### 4.7 F6 背景更换

#### 4.7.1 背景类型

| 类型 | 说明 |
| --- | --- |
| 纯色 | 取色器选色，含透明度 |
| 渐变 | 预设若干组渐变 + 自定义双色角度 |
| 预设壁纸 | 内置 6–10 张轻量壁纸（压缩后 ≤ 300KB/张） |
| 自定义上传 | 支持 jpg/png/webp，单张 ≤ 5MB，自动压缩 |
| 网络图片 URL | 填入图片地址（需用户自担跨域与失效风险） |

#### 4.7.2 图片处理链路

```
用户选择图片
   ↓
FileReader → 转 Image 对象
   ↓
Canvas 等比缩放（最长边 ≤ 2560px）
   ↓
Canvas.toBlob(quality=0.85) 压缩
   ↓
存入 IndexedDB（key: bg_{uuid}，value: Blob）
   ↓
设置中用 id 引用，渲染时 URL.createObjectURL 挂到 CSS 变量
```

**背景可调参数**：

- `模糊程度`：0–20px（`backdrop-filter` / `filter: blur()`）
- `遮罩浓度`：0–80%，保证前景文字可读性
- `填充方式`：`cover` / `contain` / `repeat`

**性能要点**：

- 大图必须压缩后再存储，防止撑爆 IndexedDB 配额。
- 渲染时只对「背景层」使用 `background-image`，避免给整个 body 加 `filter`（会导致子元素一起模糊，性能差）。
- 切换背景时释放旧的 `ObjectURL`，防止内存泄漏。
- 提供「背景轮播」可选项（P2），定时切换预设壁纸。

#### 4.7.3 主题色联动

从背景图提取主色调（`Canvas` 抽样像素求均值/中位数），自动生成卡片描边色与按钮强调色，保证整体协调。此能力可开关，默认开启。

### 4.8 F7 搜索过滤

- 顶部搜索框，输入即过滤（防抖 200ms）。
- 匹配范围：站点名称、URL、描述、标签。
- 支持 **拼音首字母** 匹配（如输入 `tx` 命中「腾讯文档」），需内置轻量拼音首字母映射表（常见汉字 3000 字左右）。
- 搜索结果高亮关键词；无结果时提示「未找到，是否添加为站点？」。
- `Enter` 打开第一个结果。

### 4.9 F8 深浅色模式

- 三态：跟随系统 / 亮色 / 暗色。
- 通过 `prefers-color-scheme` 媒体查询 + `data-theme` 属性实现。
- 所有颜色通过 CSS Variables 定义，换肤只需切换根节点属性。
- 深色模式下背景遮罩浓度自动调整，避免文字对比度不足。

### 4.10 F9 图标自动获取

采用**多级回退**策略，逐级尝试直到成功：

```
1. 用户自定义图标 URL
2. 站点 HTML 中 <link rel="icon">（需联网抓取，可选开关）
3. /favicon.ico（原生 <img onerror> 降级）
4. Google favicon 服务（默认关闭，涉及隐私外发）
5. 兜底：站点名称首字母 + 依据域名哈希生成的稳定背景色
```

**隐私原则**：所有需要外发请求的图标源默认**关闭**，由用户在设置中显式开启，并在开启时给出说明。

图标结果缓存到 IndexedDB，避免重复请求。

## 5. 数据模型设计

### 5.1 顶层结构

```json
{
  "version": 1,
  "exportedAt": "2026-10-15T13:29:00.000Z",
  "settings": { "...": "见 5.4" },
  "categories": [ "...": "见 5.2" ],
  "sites": [ "...": "见 5.3" ]
}
```

### 5.2 分类 Category

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | string | uuid |
| `name` | string | 分类名 |
| `parentId` | string \| null | 父分类 id，null 为一级 |
| `icon` | string | 图标标识（emoji 或内置 icon 名） |
| `order` | number | 排序权重，步长 100 便于插入 |
| `collapsed` | boolean | 侧栏是否折叠 |
| `createdAt` | number | 时间戳 |

### 5.3 站点 Site

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | string | uuid |
| `name` | string | 站点名称 |
| `url` | string | 完整地址 |
| `categoryId` | string | 所属分类 |
| `description` | string | 描述，可空 |
| `icon` | string | 图标 URL 或本地缓存 key，可空 |
| `tags` | string[] | 标签 |
| `pinned` | boolean | 是否置顶 |
| `openIn` | `"default"` \| `"new"` \| `"self"` | 打开方式 |
| `order` | number | 排序权重 |
| `source` | `"manual"` \| `"bookmark"` \| `"json"` | 数据来源，便于溯源 |
| `createdAt` | number | 时间戳 |
| `clickCount` | number | 点击次数，用于「常用」排序 |

### 5.4 Settings 设置

```json
{
  "theme": "auto",              // auto | light | dark
  "background": {
    "type": "preset",           // none | color | gradient | preset | upload | url
    "color": "#1e1e2e",
    "gradient": { "from": "#667eea", "to": "#764ba2", "angle": 135 },
    "imageId": "bg_xxx",        // IndexedDB 中的 key
    "url": "",
    "blur": 0,
    "overlay": 0.15,
    "fit": "cover",
    "autoThemColor": true
  },
  "layout": {
    "columns": "auto",          // auto | 3 | 4 | 5 | 6
    "cardSize": "medium",       // small | medium | large
    "showDescription": true
  },
  "behavior": {
    "defaultOpenIn": "new",
    "allowFaviconFetch": false, // 隐私开关，默认关闭
    "showClock": true
  },
  "shortcuts": { "focusSearch": "/" }
}
```

### 5.5 localStorage Key 规划

| Key | 内容 |
| --- | --- |
| `worknav:data` | 上述顶层结构（不含图片二进制） |
| `worknav:snapshot` | 上一次变更前的快照，用于回滚 |
| `worknav:meta` | schema 版本号，用于未来数据迁移 |

> **容量约束**：localStorage 单域通常 5MB。站点数据量级（1000 条 ≈ 200KB）完全够用；**图片一律走 IndexedDB**，若检测到写入超限，提示用户并引导清理背景图。

### 5.6 数据迁移

`version` 字段用于版本升级。启动时比较本地 `version` 与代码内 `SCHEMA_VERSION`，若小于则执行迁移函数链（`migrate_v1_to_v2` …），迁移前自动落一份快照。这是保证长期可维护性的关键设计，**必须在 v1 就预留**。

## 7. 关键实现要点

### 7.1 书签解析核心逻辑（伪代码）

```js
function parseBookmarks(html) {
  const doc = new DOMParser().parseFromString(html, 'text/html');
  const result = { categories: [], sites: [] };

  // 根 DL 的顶层 H3 是「收藏夹栏」，跳过，遍历其子 DL
  const rootDL = doc.querySelector('dl');
  walk(rootDL, null);

  function walk(dl, parentId) {
    const children = [...dl.children];
    for (const dt of children) {
      const h3 = dt.querySelector(':scope > h3');   // 子文件夹
      const a  = dt.querySelector(':scope > a');    // 链接
      if (h3) {
        const subDL = dt.querySelector(':scope > dl');
        const catId = createCategory(h3.textContent.trim(), parentId);
        if (subDL) walk(subDL, catId);
      } else if (a) {
        addSite({
          name: a.textContent.trim(),
          url: a.getAttribute('href'),
          icon: a.getAttribute('icon') || ''
        }, parentId);
      }
    }
  }
  return result;
}
```

**注意点**：
- 真实书签文件的 HTML 结构不规范（`<DT>`/`<DL>` 是隐式闭合的），直接用 `querySelectorAll('a')` 会丢失层级；必须按 `DT` 逐个递归。
- 需过滤 `javascript:` 伪协议与 `place:` 之类内部链接。
- 名称去重与空白清理。
- 解析过程放主线程即可（1 万条以内 < 300ms），无需 Web Worker。

### 7.2 状态管理

采用**单一数据源 + 订阅刷新**的极简模式：

```js
// store.js
const state = { data: null, ui: { keyword: '', activeCategory: 'all' } };
const listeners = new Set();

export function setState(patch, { persist = true } = {}) {
  Object.assign(state, patch);
  if (persist) Storage.save(state.data);
  listeners.forEach(fn => fn(state));
}
```

所有写操作统一走 `setState` → 触发 `render()` 全量重绘（数据量小，全量重绘足够快；卡片数超过 500 时再引入局部更新优化）。

### 7.3 性能优化清单

| 场景 | 措施 |
| --- | --- |
| 首页加载 | 数据一次性读入内存；首屏只渲染可见分类（`IntersectionObserver` 懒加载） |
| 图片 | 图标 `loading="lazy"`；背景图压缩 + 单例复用 |
| 搜索 | 输入防抖 200ms；预先构建搜索索引字符串 |
| 渲染 | 使用 `DocumentFragment` 批量插入，减少重排 |
| 存储 | 写入做 500ms 防抖，避免频繁 IO |

### 7.4 安全与隐私

| 项 | 措施 |
| --- | --- |
| URL 注入 | 渲染时校验协议白名单（仅 http/https），拒绝 `javascript:`；使用 `textContent` 而非 `innerHTML` 插入用户数据 |
| 前台图标抓取 | 默认关闭，开启时明确告知会向第三方域名发起请求 |
| 数据外发 | 全站无任何埋点、无远程接口，除用户主动开启的图标抓取外全程离线 |
| 导入文件 | 仅本地 FileReader 解析，不上传 |
| JSON 导入校验 | 严格校验结构与字段类型，非法字段丢弃而非直接信任 |

### 7.5 发布与静态资源注意事项（踩坑记录）

平台发布走 Page 事务（create → upload → commit → publish）。上传产物时若不带 `Content-Type`，对象存储会把文件存成 `application/x-www-form-urlencoded`，而静态站响应同时带 `X-Content-Type-Options: nosniff`，浏览器会**直接拒绝执行 js、拒绝解析 css**。

故障表现很有迷惑性：HTML 和平台注入脚本正常，所以顶栏、侧栏骨架能显示，但**背景层没有渐变、卡片区一片空白、分类列表为空**——看起来像「背景丢了」，实际是整个 `app.js` 没跑起来。

因此重新上传资源时必须显式指定类型：

| 扩展名 | Content-Type |
| --- | --- |
| `.js` | `application/javascript; charset=utf-8` |
| `.css` | `text/css; charset=utf-8` |
| `.svg` | `image/svg+xml` |
| `.webmanifest` | `application/manifest+json; charset=utf-8` |
| `.html` | `text/html; charset=utf-8`（平台会强制，一般无需干预） |

发布后核对两件事：

1. `curl -sI <资源地址>` 确认 `content-type` 正确；
2. 用无头浏览器截图首屏，确认背景渐变与卡片都渲染出来（只看 HTTP 200 不够，200 也可能是被拦下来的资源）。
